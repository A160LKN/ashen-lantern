# Пепельный Фонарь (Ashen Lantern)

[![CI](https://github.com/A160LKN/ashen-lantern/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/A160LKN/ashen-lantern/actions/workflows/ci.yml)
[![Demo](https://img.shields.io/badge/играть-GitHub_Pages-f2c443)](https://a160lkn.github.io/ashen-lantern/)

2D pixel art action-RPG для браузера: тёмное фэнтези, вид сверху, атмосферное освещение.
Стек: **TypeScript + Phaser 3.90 + Vite**. Графика и звук генерируются кодом — внешних ассетов нет.

**[▶ Играть в браузере](https://a160lkn.github.io/ashen-lantern/)** · [Тестовая документация](docs/qa/README.md) · [Баг-репорты](docs/qa/bug-reports/README.md) · [Аудит](docs/qa/audit.md)

**Тестовый API для автоматизации.** Игра рисуется на canvas и живёт в реальном времени — через DOM её не протестировать.
Поэтому в dev-сборке и с параметром `?test` доступен `window.__ashen`: снимок состояния (здоровье, инвентарь, враги и
состояния их ИИ), прогон ровно N кадров, телепорт, бессмертие, переход на уровень. Проверки, зависящие от времени,
прогоняют кадры синхронно и не зависят от скорости машины. Параметр `?profile=имя` даёт отдельное хранилище, чтобы
тесты не трогали сохранения игрока. Подробнее — в [docs/qa](docs/qa/README.md#тестовый-api-аналог-чит-консоли).

## Быстрый старт

```bash
npm install
```

```bash
npm run dev          # http://localhost:5173
```

```bash
npm run test:all     # линтер, типы, юнит с покрытием, E2E
```

Отдельно: `npm test` (юнит), `npm run test:coverage`, `npm run test:e2e` (поднимет production-сборку на порту 4173),
`npm run build` (сборка в `dist/`). Перед первым запуском E2E: `npx playwright install chromium firefox`.

## 1. Game Design Document (кратко)

**Почему такой выбор.** Жанр — *action-RPG с элементами survival*: вид сверху лучше всего читается в пиксельной графике 16×16,
даёт простор для исследования, боя и ИИ врагов. Сеттинг — *тёмное фэнтези*: позволяет сделать освещение центральной механикой,
а не только украшением.

**Сюжет.** Пепельный Король погасил маяки, и мир поглощает тьма. Носитель Фонаря проходит три земли, собирает Осколки Угля
и зажигает маяки, открывающие путь дальше.

**Игровой цикл.** Исследовать уровень во тьме → сражаться с врагами → собирать монеты, зелья, масло, ключи, осколки →
улучшаться в святилище → зажечь маяк → портал на следующий уровень.

**Ключевая механика — свет.** Фонарь постоянно тратит масло; радиус света зависит от его запаса (45–100%).
Масло находится в мире, в сундуках и выпадает из врагов. Улучшение «Пламя фонаря» увеличивает радиус и замедляет расход.

**Уровни.**

1. *Тлеющий лес* — сумерки, ручей с мостами, руины с запертой дверью. Враги: слизни, скелеты.
2. *Затопленный склеп* — почти полная темнота, залы и коридоры, две запертые двери. Скелеты, пепельные духи (стрелки).
3. *Цитадель Пепла* — лава, два крыла, тронный зал с боссом. Третий осколок выпадает из Пепельного Короля.

**Прогрессия.** Опыт → уровни персонажа (+здоровье, +урон, полное исцеление). Монеты → 5 улучшений по 5 уровней.
Сложность растёт от уровня к уровню (множители здоровья/урона врагов) и выбирается в настройках (лёгкая/обычная/тяжёлая).
Задания: основные (осколки, маяк, босс) и побочные от NPC с наградой. 12 достижений.

**Визуальный стиль.** Тайлы 16×16, камера ×3 (320×180 игровых пикселей на экране), единая палитра (`src/graphics/palette.ts`),
обводка силуэтов, тени, многослойный мир (земля → препятствия → персонажи с сортировкой по глубине → кроны деревьев →
темнота со ступенчатыми «пиксельными» пятнами света → аддитивное свечение → частицы).

## 2. Архитектура

```
src/
  main.ts                 конфигурация Phaser, загрузка шрифта, список сцен
  config.ts               константы (размеры, слои глубины, версия сохранений)
  core/                   без зависимостей от движка
    StateMachine.ts       универсальный конечный автомат (ИИ врагов и босса)
    EventBus.ts           шина событий игра ↔ интерфейс
    rng.ts                детерминированный ГСЧ и хэши
  data/                   данные — расширяются без изменения кода
    levels.ts             ASCII-карты уровней, NPC, параметры тьмы и музыки
    enemies.ts            характеристики врагов
    upgrades.ts quests.ts achievements.ts
  world/
    grid.ts               сетка проходимости, прямая видимость, A*, flood fill (чистая логика)
    levelParser.ts        разбор ASCII-карты (чистая логика)
    LevelBuilder.ts       построение тайловой карты Phaser, анимация воды/лавы
    Lighting.ts           слой темноты + источники света
  entities/
    Player.ts             управление, бег, атака, урон
    Enemy.ts              ИИ на FSM: idle/patrol/chase/attack/return/hurt
    Boss.ts               босс: dormant/chase/slam/ring/summon/dash, 2 фазы
  graphics/               процедурная пиксельная графика (Canvas)
    tiles.ts characters.ts objects.ts ui.ts palette.ts canvas.ts
    TextureFactory.ts     регистрация текстур и анимаций в Phaser
  systems/
    GameState.ts          сериализуемое состояние и правила прогрессии (чистая логика)
    SaveSystem.ts         сохранения: версия, контрольная сумма, миграция, очистка
    Quests.ts Achievements.ts Settings.ts Storage.ts
    Audio.ts              синтез WebAudio: эффекты, музыка-секвенсор, атмосфера
    Session.ts            текущая сессия и переходы между сценами
  scenes/
    BootScene MenuScene GameScene UIScene overlays.ts (пауза, настройки, сохранение/загрузка,
    инвентарь, святилище, достижения, помощь, поражение, победа)
  ui/widgets.ts           панели, кнопки, клавиатурная навигация
  testing/testHooks.ts    тестовый API (только dev или ?test)
tests/                    Vitest: уровни, A*/FSM, прогрессия, лут, сохранения, контракт по схеме
e2e/                      Playwright: сквозные сценарии в браузере
schemas/save.schema.json  контракт файла сохранения
docs/qa/                  тест-план, кейсы, чек-листы, баг-репорты, отчёт, аудит
```

**Зависимости между системами.** `data` и `core` ни от чего не зависят. `systems/*` (кроме Audio/Session) и `world/grid`,
`world/levelParser` — чистая логика без Phaser, поэтому покрыты тестами. `GameScene` связывает мир, сущности и системы,
реализуя интерфейс `EnemyWorld` (враги не знают о сцене). `UIScene` читает `Session` и слушает `EventBus`.

**Как расширять.**
- *Новый уровень* — добавить объект в `LEVELS` (ASCII-карта + NPC). Тест `levels.test.ts` автоматически проверит,
  что все осколки, ключи, двери и маяк достижимы.
- *Новый враг* — запись в `ENEMIES`, символ в `ENEMY_CHARS`, спрайт в `characters.ts`; поведение — через `attack`
  (`leap` / `melee` / `ranged`) или подкласс `Enemy`.
- *Замена графики на PNG* — загрузить PNG в `BootScene.preload` с тем же ключом и раскладкой кадров
  (персонажи: 30 кадров 16×16 — 3 направления × 10 кадров; босс: 12 кадров 32×32), `TextureFactory` пропускает
  уже существующие ключи.

## 3. Реализованные механики

- **Управление:** движение в 8 направлениях, бег с выносливостью, удар в сторону взгляда или курсора, взаимодействие, зелья.
- **Персонаж:** здоровье, выносливость, масло, урон/крит, скорость, радиус света; анимации ожидания, ходьбы, атаки,
  получения урона (кадр + вспышка + отбрасывание + неуязвимость).
- **Бой:** дуга удара, критические удары, числа урона, искры, тряска камеры, разрушаемые горшки.
- **ИИ (FSM):** патрулирование вокруг «дома», обнаружение по дистанции и прямой видимости (значок «!»), преследование
  напрямую или по пути A*, обход препятствий и детектор застревания, атака с предупреждающим замахом, потеря цели
  через 3 с или при уходе от «поводка» → возврат домой.
  Слизень — прыжок, скелет — удар мечом, дух — держит дистанцию и стреляет сферами.
- **Босс:** пробуждение при виде игрока, удар по земле с индикатором области, огненные кольца, во 2-й фазе —
  призыв скелетов, рывок, усиленные кольца; полоса здоровья и боевая музыка.
- **Мир:** 3 уровня, вода/лава с анимацией, мосты, деревья с кронами поверх персонажа, сундуки, запертые двери и ключи,
  жаровни, святилища, маяки-порталы, NPC с диалогами.
- **Прогрессия:** опыт и уровни, 5 улучшений, основные и побочные задания с наградами, 12 достижений.
- **Интерфейс:** главное меню, HUD (полосы, счётчики, трекер заданий, подсказки, уведомления, диалоги, полоса босса),
  пауза, инвентарь/журнал, святилище, настройки, сохранение/загрузка (автослот + 3 ручных, удаление),
  достижения, «Как играть», экраны поражения и победы. Всё управляется мышью и клавиатурой.
- **Звук:** процедурная музыка для меню, каждого уровня, босса и победы; шаги, удары, урон, подбор, кнопки и др.;
  фоновая атмосфера (ветер и сверчки / капли / гул и треск). Раздельная громкость музыки и эффектов.
- **Сохранения:** уровень, характеристики, улучшения, инвентарь, задания, статистика, состояние объектов уровня,
  контрольная точка. Автосохранение при входе на уровень, у святилища, после маяка и босса.
  Повреждённые сохранения (битый JSON, неверная контрольная сумма, будущая версия) распознаются и помечаются;
  устаревший формат v1 мигрирует; значения вне допустимых диапазонов ограничиваются.
  Достижения и статистика гибелей/побед хранятся в профиле, общем для всех сохранений.

## 5. Ограничения

- Позиция героя сохраняется как последняя контрольная точка (святилище или начало уровня), а не точные координаты;
  враги при загрузке появляются заново, подобранные предметы и открытые объекты — нет.
- Звук синтезируется на лету: он есть, но это простые чиптюн-тембры, а не записанные треки.
  До первого нажатия клавиши/клика звук не включается (политика браузеров).
- Реальный FPS на типичном ПК и прохождение игроками не замерялись; баланс (урон, здоровье босса, цены) выверен
  расчётом, а не плейтестами. Звук на слух не проверялся. Что именно не покрыто — в [матрице трассировки](docs/qa/traceability.md).
- Геймпад и сенсорное управление не поддерживаются; рассчитано на ПК с клавиатурой и мышью.
