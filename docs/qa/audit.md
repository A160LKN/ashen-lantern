## 2. Тестирование и процесс

| Находка | Решение |
| --- | --- |
| Не было E2E: связки сцен, ввода и рендера не проверялись автоматически | 16 сценариев на Playwright против production-сборки, Chromium и Firefox, `7301643` |
| Не было CI: тесты запускались только вручную | GitHub Actions: линтер, типы, юнит с покрытием, сборка, E2E в двух браузерах, `7301643` |
| Покрытие не измерялось | v8-покрытие модулей логики с порогами (строки 90%, ветви 85%, функции 90%); фактически 97,9 / 89,6 / 99,0. Чтобы пройти порог по функциям, дописаны тесты на ГСЧ, `formatTime`, падение localStorage — а не снижен порог, `e21116f` |
| Формат сохранения не был зафиксирован как контракт | JSON Schema + контрактные тесты + фаззинг 500 случайных входов, `e21116f` |
| Игру нельзя было автоматизировать: всё рисуется на canvas, время реальное | Тестовый API `window.__ashen` (только dev или `?test`): снимок состояния, пошаговые кадры, читы, `e21116f` |
| Ручные проверки портили бы сохранения игрока | Параметр `?profile=имя` — изолированное хранилище, `e21116f` |
| Не было тестовой документации и шаблона баг-репорта | [docs/qa](README.md), шаблон issue в `.github/ISSUE_TEMPLATE` |
| *Рекомендация:* визуальные регрессионные тесты (скриншоты) | Не сделано: частицы и мерцание света случайны. Нужен режим с фиксированным seed и отключёнными частицами — тогда `toHaveScreenshot` станет стабильным |
| *Рекомендация:* плейтест с людьми для баланса | Баланс урона, здоровья и цен рассчитан, но не проверен игроками; нужна 1–2 сессии с замером времени прохождения и числа смертей |

## 3. Качество кода и инструменты

| Находка | Решение |
| --- | --- |
| Не было линтера | ESLint + typescript-eslint, `eqeqeq`, запрет `console`; найдено и исправлено 1 замечание, `e21116f` |
| TypeScript 7 несовместим с typescript-eslint: у TS 7 нет JS API, установка падала с конфликтом зависимостей | TypeScript закреплён на 6.0 (поддерживаемый диапазон `<6.1`); Dependabot не предлагает обновление выше, `e21116f` |
| Трекер заданий в HUD пересоздавал панель и тексты каждую секунду | Перерисовка только при изменении заданий, `f1c7952` |
| *Рекомендация:* строгая типизация разбора сохранений | В `sanitize` используется `any` для недоверенного ввода — каждое поле проверяется вручную, а фаззинг подтверждает результат. Можно заменить на схему-валидатор (Zod), но это ещё одна зависимость |
