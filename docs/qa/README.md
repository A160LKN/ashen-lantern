## Инструменты

| Задача | Инструмент |
| --- | --- |
| Юнит- и контрактные тесты логики | Vitest, покрытие v8 |
| Контракт формата сохранений | JSON Schema (draft-07), Ajv |
| Фаззинг входных данных | генератор случайных сохранений с фиксированным seed |
| E2E в браузере | Playwright (Chromium, Firefox), трейсы, видео и скриншоты при падении |
| Статический анализ | TypeScript strict, ESLint + typescript-eslint |
| Статическая проверка уровней | BFS по сетке проходимости с симуляцией ключей и дверей |
| CI/CD | GitHub Actions: проверки на каждый push и PR, демо на Pages только после зелёного CI |
| Отладка и воспроизведение | тестовый API `window.__ashen` (снимок состояния, пошаговые кадры, читы), DevTools |

## Тестовый API (аналог чит-консоли)

Игры трудно автоматизировать через интерфейс: всё рисуется на canvas, а время идёт в реальном темпе.
Поэтому в игре есть тестовый API — он включается только в dev-сборке или с параметром `?test`:

```js
__ashen.state()                     // уровень, здоровье, инвентарь, задания, позиция героя, враги и их состояния ИИ
__ashen.step(36)                    // прогнать ровно 36 кадров (0,6 с) — проверки не зависят от скорости машины
__ashen.cheats.teleport(35, 20)     // переместить героя на клетку
__ashen.cheats.godMode(true)        // бессмертие для проверки длинных сценариев
__ashen.cheats.loadLevel(2)         // сразу на уровень с боссом
```

Параметр `?profile=имя` даёт отдельное хранилище: ручные проверки и автотесты не портят сохранения игрока.
Отсутствие API без `?test` проверяется отдельным E2E-тестом.

## Почему здесь нет API-тестов

У игры нет сервера: она целиком работает в браузере, а данные хранятся в localStorage.
Ближайший аналог API здесь — формат файла сохранения. Он описан JSON Schema и покрыт контрактными тестами
([tests/saveContract.test.ts](../../tests/saveContract.test.ts)). Тестирование REST API показано в других проектах автора.
