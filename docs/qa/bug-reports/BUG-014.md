# BUG-014 · Музыка не запускается, если звук «просыпается» после первого нажатия

| Поле | Значение |
| --- | --- |
| Severity / Priority | S3 Major / P2 |
| Область | Звук |
| Воспроизводимость | В браузерах, где звуковой контекст стартует приостановленным (например, Safari) или не запускается с первого жеста |
| Статус | Исправлен |

**Как найден:** новый E2E-тест звука упал в Firefox на CI: контекст остался `suspended`. Причина в CI — нет звукового
устройства, но при разборе кода выяснилось, что движок вообще не умеет «догонять» запуск звука.

**Шаги (юнит-тест с поддельным AudioContext)**
1. До первого нажатия запросить музыку меню — трек уходит в очередь.
2. Первое нажатие: контекст создан, `resume()` вызван, но контекст ещё `suspended`.
3. Контекст переходит в `running` (так браузер завершает асинхронный `resume()`).

**Фактический результат:** музыка и фоновые звуки не начинаются (`sequencer: false`) — до следующей смены трека.
Если первый жест не смог запустить звук, следующие нажатия его тоже не будили.

**Ожидаемый результат:** как только контекст заработал, начинаются отложенная музыка и фон.

**Исправление (`src/systems/Audio.ts`):** обработчик `onstatechange` запускает отложенные музыку и фон; каждое следующее
нажатие клавиши, клик или касание повторно вызывает `resume()`, пока звук не заработает. Заодно новая смена трека
отменяет устаревший отложенный, чтобы после пробуждения не заиграла не та музыка.

**Регресс:** `tests/audio.test.ts` — 3 теста; первый падает без исправления. E2E «Звук…» в Chromium проверяет работающий
звук, а в Firefox без звукового устройства — что трек уровня стоит в очереди.
