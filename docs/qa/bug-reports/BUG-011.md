# BUG-011 · При низком FPS одно нажатие в меню срабатывает несколько раз

| Поле | Значение |
| --- | --- |
| Severity / Priority | S3 Major / P1 |
| Область | Интерфейс, управление |
| Воспроизводимость | Всегда, если за один кадр пришло несколько событий клавиатуры |
| Статус | Исправлен |

**Как найден:** после исправления BUG-010 в Firefox на CI остались два нестабильных теста. В CI Firefox не получает
WebGL и рисует через Canvas — кадры медленные. Чтобы не гадать, в тестовый API добавлен журнал событий клавиатуры
(DOM-события и вызовы обработчиков меню с номером кадра); тесты прикладывают его к отчёту. Многократный прогон
(`--repeat-each=6`) дал 7 падений из 42, и журнал показал причину.

**Данные из журнала (Firefox, CI):** два нажатия ArrowLeft в кадре 50, а обработчик меню настроек вызван 5 раз:
```
dom  keydown ArrowLeft  frame 50  → menu:Settings handled
dom  keyup   ArrowLeft  frame 50
dom  keydown ArrowLeft  frame 50  → menu:Settings handled ×2
dom  keyup   ArrowLeft  frame 50  → menu:Settings handled ×2
```

**Шаги (детерминированно, Chromium)**
1. Меню → Настройки, фокус на «Музыка» (50%).
2. Остановить цикл кадров (`__ashen.pauseLoop()`).
3. Дважды нажать стрелку влево.
4. Прогнать 2 кадра.

**Фактический результат:** громкость 0% вместо 30%. На экране то же, что на скриншоте падения в CI.
В тесте сохранения так же задвоилась стрелка вниз в меню паузы: вместо «Сохранить» открылось «Загрузить», и игра
не сохранилась.

**Ожидаемый результат:** каждое нажатие обрабатывается ровно один раз.

**Влияние на игрока:** на слабом ПК — двойные покупки улучшений, пропуск строк диалога, «прыжки» по пунктам меню.

**Причина:** подписка на событие `keydown` плагина клавиатуры Phaser. Плагин хранит очередь событий до конца кадра и при
каждом новом DOM-событии заново рассылает события из очереди, поэтому при нескольких событиях за кадр обработчик
получает повторы.

**Исправление:** функция `onSceneKeyDown` (`src/ui/widgets.ts`) слушает DOM напрямую и вызывает обработчик, только пока
сцена запущена. На неё переведены меню, диалоги, инвентарь и разовые действия в игре.

**Регресс:** E2E «несколько нажатий за один кадр обрабатываются ровно по одному разу» — падает без исправления
(громкость 0), проходит с ним. Прогоняется в Chromium и Firefox.
